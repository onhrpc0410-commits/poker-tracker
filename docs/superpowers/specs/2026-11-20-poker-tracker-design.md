# Poker Tracker 設計書

## 目的・背景
友人との賭けポーカー(トランプは現物を使用)で、持ち金をスマホのメモに手書きしており、金額がよくズレる。
**お金の動きだけを正確に記録・集計するアプリ**を作る。カードや手札、役判定は一切扱わない。

## ゴール
- 全員の残高とポットが常に正しい。
- 1台のiPadを全員で見ながら、順番にボタンを押して進行できる。
- セッション終了時に、各自の勝ち負けが分かる。ハンドごとの履歴も見返せる。

## 非ゴール
- カード表示、役判定、勝者の自動判定。
- サイドポット(all in の上限を決めるので考えない)。
- 複数端末の同期、サーバー、ログイン。
- 過去日ごとの成績の集計(今日のセッションと、そのハンド履歴のみ)。

## アンチゴール(技術的に動いても失敗とみなす)
- 見た目がAIっぽい、おしゃれ、にぎやか。
- 押し間違いで金額がズレて戻せない。

## 対象端末・制約
- 主: iPad Air 11インチ(横向き)。副: スマホ横向き。
- iPadのSafariで動くこと。新しすぎるJS機能は避ける。
- データは端末のlocalStorageに保存。消えない前提だが、ブラウザのデータ削除で消えることはREADMEに注意書きする。

## 採用した方式(Approaches)
- **案A: 素のHTML/CSS/JavaScript** — 採用。ビルド不要で、規模に対して十分。欠点はコードが散らかりやすいこと。ファイルを分けて対処する。
- 案B: React + Vite — 不採用。Node.jsの導入が必要で、この規模では過剰。
- **案C: PWA対応(ホーム画面に追加、オフライン動作)** — 案Aに追加して採用。
- 公開: GitHub Pagesで配信する。そのためリポジトリはpublicにする(ユーザー決定)。名前や残高は各端末内にのみ保存され、リポジトリには入らない。

## 機能仕様

### プレイヤー管理
- 登録(名前のみ。残高は0円から開始)。名前と現在の残高は永久に保存する。
- 残高は「持ち金」ではなく**収支**。負けた人はマイナスで表示する(例: -1,000)。残高の下限はなく、足りなくて参加できない、という制限は設けない。
- 削除。残高の手動調整(+/-の入力)。

### ゲーム設定
- 参加プレイヤーの選択。**座っている順にタップして席順を決める**。席順は反時計回りとして扱う。
- レイズ幅(例: 100円ずつ)。
- all in の上限(1ハンドで1人が出せる最大額)。

### ハンドの進行
1. **ブラインド役**: 1ハンドにつき1人。ハンドごとに席順で1人ずつ移る(反時計回り)。ブラインド役はレイズ幅1つ分を自動でポットに入れる。
2. ブラインド役の**次の人**から行動を始める。
3. 操作ボタン:
   - **CALL**(賭け金が0のときは **CHECK**)。現在の賭け金を表示する。
   - **RAISE**: レイズ幅の倍数で上げる。
   - **ALL IN**: 設定した上限額をそのまま出す(残高に関係なく常に上限額)。
   - **FOLD**。
4. ラウンド終了: 残っている全員が同額を出し、全員が1回は行動した時点。ブラインド役は一周して戻ったとき、CHECKまたはRAISEができる。
5. 「NEXT ROUND」を押すと、そのラウンドの賭け金をリセットして次のラウンドに進む(フロップ等の区別はアプリでは持たない)。
6. 1人を残して全員がFOLDしたら、その人が勝者になる。それ以外は「SHOWDOWN」を押して勝者を選ぶ(引き分けは複数選択で山分け)。
7. ポットが勝者の残高に加算され、次のハンドへ(ブラインド役が次の席へ移動)。
- **UNDO**: 直前の操作を取り消せる。

### 集計
- セッション開始時の残高を記録し、「現在残高 − 開始残高」を各自の勝ち負けとして表示する。
- ハンドごとの履歴を保存する: ブラインド役、各自の操作、ポット、勝者、残高の変化。

### 画面・見た目
- 英語ベースの表記(ALL IN、CALL、RAISE、FOLD、CHECK、POT など)。
- 白黒が基本。色を足す場合は緑。
- シンプルで素っ気ない、チープな見た目。
- **ポットは背景に大きく薄く常時表示**し、全員が見やすいようにする。
- 現在の手番の人を分かりやすく示す。

## 私の判断(要確認)
- RAISEは「+/-で額を選んで確定」の形にする。具体的なUIは実装時に決める。
- 残高がマイナスでも、全員が常に参加でき、ブラインドや賭けも普通に行う。
- 2ラウンド目以降の最初の行動者は、ブラインド役の次の、フォールドしていない人にする。
- 実行中のセッションは自動保存し、ページを再読み込みしても続きから再開できる。
- 手動の残高調整は履歴に記録する。

## 実装者に任せる点
- ファイル分割、コードの細部、レイアウトの寸法、テストの書き方。
- 細かい挙動の迷いは、この設計書の目的(お金をズレなく記録する)に沿って決める。
